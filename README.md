# LUFLY Catalog Manager

نظام إدارة كتالوج منتجات LUFLY مبني بـ PHP و MySQL. مصمم للتشغيل المحلي على XAMPP.

## المميزات

✅ **عرض المنتجات** - 715 منتج مقسمين حسب الكود (42 مجموعة)  
✅ **تعديل كامل** - تعديل الكود، الوصف، الحالة، الماركة، والملاحظات  
✅ **إدارة الصور** - رفع صور جديدة، حذف صور قديمة، تغيير الترتيب
✅ **تحسين الصور بموافقة المستخدم** - معاينة قبل/بعد، واعتماد التحسين أو الاحتفاظ بالأصل
✅ **بحث سريع** - بحث بالكود أو الوصف  
✅ **تجميع بالكود** - المنتجات متجمعة حسب الـ code prefix  
✅ **أرشيف** - أرشفة المنتجات بدون حذفها  
✅ **إحصائيات** - عدد المنتجات، المرفقات، والمجموعات  
✅ **إعدادات** - تغيير الألوان والعنوان  
✅ **واجهة عربية** - RTL كاملة  
✅ **كشف التكرار** - تنبيه عند وجود كود مكرر أو بيانات ناقصة  

## تشغيل اللوكال بدون قاعدة بيانات

الاختيار الافتراضي `APP_STORAGE=auto`: على localhost يقرأ ويحفظ الكتالوج في **ملف JSON محمي** داخل `data/local/`، والصور المرفوعة محليًا داخل `uploads/local/`، بدون فتح MySQL أو SQLite. على الاستضافة استخدم `APP_STORAGE=database` للاعتماد على قاعدة البيانات.

التعديلات القديمة في SQL لا تُنقل تلقائيًا ولا تُحذف. توجد أداة تصدير اختيارية للانتقال مع الحفاظ على بياناتك.

**التفاصيل والتصدير والنسخ الاحتياطي:** [LOCAL_STORAGE.md](LOCAL_STORAGE.md).

## التشغيل على XAMPP

### 1. تجهيز XAMPP
- شغّل Apache. MySQL مطلوب فقط لو اخترت `APP_STORAGE=database`.
- PHP 8.1+ مطلوب

### 2. إعداد PHP (في php.ini)
```ini
upload_max_filesize = 12M
post_max_size = 128M
max_file_uploads = 30
extension=pdo_mysql
extension=fileinfo
extension=gd ; مطلوب لميزة تحسين الصور
```

### 3. نسخ الملفات
انسخ الريبو في:
```
xampp/htdocs/lufly/
```

### 4. تشغيل النظام
افتح المتصفح على:
```
http://localhost/lufly/
```

**في وضع database، أول مرة هيعمل install تلقائي:**
- هيعمل database اسمها `lufly_catalog`
- هيستورد 715 منتج من `data/catalog.json`
- هيستورد 1,465 مرفق (صور ورسومات)

### 5. تعديل إعدادات الاتصال (اختياري)
لو MySQL مش على الإعدادات الافتراضية، اعمل ملف `config.local.php`:
```php
<?php
return [
    'host' => '127.0.0.1',
    'port' => 3306,
    'database' => 'lufly_catalog',
    'username' => 'root',
    'password' => '', // كلمة سر MySQL
];
```

## تحسين صورة موجودة

افتح الصورة بالحجم الكبير واختر نوع التحسين قبل الضغط على **تحسين الصورة**:

- **منتجات بيضاء — تحسين قوي محلي**: إبراز الحواف والظلال والتباين الموضعي مع حماية الأبيض والشفافية. يعمل بـGD بدون Python، وليس ذكاءً اصطناعيًا ولا يغيّر الأبعاد.
- **AI ×2**: نموذج **FSRCNN** عصبي حقيقي، مع معالجة مخصصة للمنتجات البيضاء. يضاعف العرض والارتفاع، ويعمل محليًا على CPU دون إرسال الصور لخدمة خارجية. يحتاج Python وOpenCV contrib وإعداد مسار المفسّر؛ النموذج المسبق التدريب مرفق برخصته، ولا يتم تنزيله أثناء التشغيل.

تظهر الصورة الأصلية والنتيجة للمقارنة مع اسم المحرك والأبعاد. فعّل **فحص التفاصيل بالحجم الفعلي (100٪)** لرؤية التفاصيل بدل تصغير الصورتين. اضغط **✓ اعتماد التحسين واستبدال الصورة** للحفظ، أو **إلغاء والاحتفاظ بالأصل** لتركها كما هي. لا يتغير الأصل قبل الموافقة، وتظل حماية الصور المشتركة والمعاينات القديمة فعّالة.

- المحلي: حتى 6 ميجابكسل و12 ميجابايت مع فحص الذاكرة؛ AI: حتى 1.5 ميجابكسل قبل التكبير (6 ميجابكسل بعده)، ومهلة معالجة 30 ثانية.
- JPG/PNG/WebP ثابتة فقط، والنتيجة PNG مع الشفافية. تُرفض GIF وWebP المتحركة لتجنب فقد الحركة.
- المعاينة خاصة بالجلسة، لمدة 10 دقائق، وبحد أقصى 3 معاينات. تُنظف عند الإلغاء/الاعتماد/الخروج، والمنتهية عند طلبات لاحقة.
- يلزم GD وصلاحيات المجلد المؤقت و`uploads`؛ EXIF موصى به لصور الكاميرا. مسار AI يحتاج أيضًا `proc_open` وPython؛ عند فشله يظهر خطأ ولا يُستبدل بتحسين محلي متنكّر كـAI.
- لا يضمن أي وضع استرجاع التفاصيل المفقودة. راجع الحواف والألوان قبل الموافقة، خصوصًا مع الصور العصبية.

**دليل إعداد Linux وWindows/XAMPP:** [tools/image_enhancement/README.md](tools/image_enhancement/README.md).

## تجميع المنتجات بالكود

كل منتج ليه code مثل `1520-015`. النظام بيجمع المنتجات حسب الجزء اللي قبل الـ `-`:
- `1520-015` → مجموعة `1520`
- `1520-2030` → مجموعة `1520`
- `1610-0185` → مجموعة `1610`

ده بيسهل تحديد المنتجات اللي من نفس الصنف أو الكتيجوري.

## الأمان

⚠️ **النظام ده للاستخدام المحلي فقط!**  
- يوجد تسجيل دخول عند ضبط `APP_PASSWORD` في `.env`؛ لا تتركه فارغًا لو الجهاز متاح لمستخدمين آخرين.
- لا تعرضه على الإنترنت
- الـ .htaccess بيحمي الملفات الحساسة
- CSRF protection على كل الـ forms
- Prepared statements ضد SQL injection
