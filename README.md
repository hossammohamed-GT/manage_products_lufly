# LUFLY Catalog Manager

نظام إدارة كتالوج منتجات LUFLY مبني بـ PHP و MySQL. مصمم للتشغيل المحلي على XAMPP.

## المميزات

✅ **عرض المنتجات** - 713 منتج مقسمين حسب الكود (40 مجموعة)  
✅ **تعديل كامل** - تعديل الكود، الوصف، الحالة، الماركة، والملاحظات  
✅ **إدارة الصور** - رفع صور جديدة، حذف صور قديمة، تغيير الترتيب
✅ **تحسين الصور بموافقة المستخدم** - معاينة قبل/بعد، واعتماد التحسين أو الاحتفاظ بالأصل
✅ **بحث سريع** - بحث بالكود أو الوصف  
✅ **تجميع بالكود** - المنتجات متجمعة حسب الـ code prefix  
✅ **أرشيف** - أرشفة المنتجات بدون حذفها  
✅ **إحصائيات** - عدد المنتجات، المرفقات، والمجموعات  
✅ **إعدادات** - تغيير الألوان والعنوان  
✅ **واجهة عربية** - RTL كاملة  
✅ **كشف التكرار** - تنبيه عند وجود كود مكرر أو بيانات ناقصة  

## التشغيل على XAMPP

### 1. تجهيز XAMPP
- تأكد إن Apache و MySQL شغالين
- PHP 8.1+ مطلوب

### 2. إعداد PHP (في php.ini)
```ini
upload_max_filesize = 12M
post_max_size = 128M
max_file_uploads = 30
extension=pdo_mysql
extension=fileinfo
extension=gd ; مطلوب لميزة تحسين الصور
```

### 3. نسخ الملفات
انسخ الريبو في:
```
xampp/htdocs/lufly/
```

### 4. تشغيل النظام
افتح المتصفح على:
```
http://localhost/lufly/
```

**أول مرة هيعمل install تلقائي:**
- بوضع `APP_STORAGE=auto` الافتراضي، التشغيل على localhost بيستخدم ملفات JSON محلية (`data/local/`) من غير MySQL — راجع [LOCAL_STORAGE.md](LOCAL_STORAGE.md). ولو عايز MySQL لوكال حط `APP_STORAGE=database` في `.env` وهيعمل database اسمها `lufly_catalog`
- هيستورد 713 منتج من `data/catalog.json` (بتعديلات الاستضافة وحالات التأكيد)
- هيستورد 1,495 مرفق (صور ورسومات)

### 5. تعديل إعدادات الاتصال (اختياري)
لو MySQL مش على الإعدادات الافتراضية، اعمل ملف `config.local.php`:
```php
<?php
return [
    'host' => '127.0.0.1',
    'port' => 3306,
    'database' => 'lufly_catalog',
    'username' => 'root',
    'password' => '', // كلمة سر MySQL
];
```

## تحسين صورة موجودة

1. اضغط على صورة المنتج لفتحها بالحجم الكبير، ثم اختر **تحسين الصورة**.
2. سيظهر الأصل ونسخة محسّنة للمقارنة؛ التحسين خفيف للحدة والتباين، بدون تكبير أو توليد تفاصيل بالذكاء الاصطناعي.
3. اضغط **✓ اعتماد التحسين واستبدال الصورة** لحفظ النسخة الجديدة وتحديث صورة الكارت، أو **إلغاء والاحتفاظ بالأصل** لعدم تغيير أي شيء.

الصورة الأصلية لا تتغير بمجرد تجهيز المعاينة. عند الاعتماد تُستبدل إحالة الصورة المحددة فقط، وتظل الملفات المشتركة مع منتجات أخرى محفوظة. لن يُقبل التحسين إذا حُذفت الصورة أو استُبدلت أو أُرشف المنتج أثناء المعاينة.

- يتطلب PHP GD مع دعم نوع الصورة، وصلاحية الكتابة في مجلد النظام المؤقت و`uploads`؛ يوصى بتفعيل EXIF لضبط اتجاه صور الكاميرا JPEG.
- يدعم الصور الثابتة JPG وPNG وWebP؛ تُحفظ النتيجة بصيغة PNG مع الحفاظ على الشفافية. GIF وWebP المتحرك غير مدعومين لتجنب فقد الحركة.
- الحد الأقصى 6 ميجابكسل و12 ميجابايت للصورة الأصلية، مع فحص الذاكرة المتاحة قبل المعالجة.
- المعاينة خاصة بالجلسة وصالحة لمدة 10 دقائق، وبحد أقصى 3 معاينات في الجلسة. تُزال الملفات المؤقتة عند الإلغاء أو الاعتماد أو تسجيل الخروج، وتُجمع المعاينات المتروكة المنتهية عند طلبات تحسين لاحقة.
- التحسين ليس ضمانًا لاسترجاع التفاصيل المفقودة؛ المستخدم يقرر بعد المقارنة.

## تجميع المنتجات بالكود

كل منتج ليه code مثل `1520-015`. النظام بيجمع المنتجات حسب الجزء اللي قبل الـ `-`:
- `1520-015` → مجموعة `1520`
- `1520-2030` → مجموعة `1520`
- `1610-0185` → مجموعة `1610`

ده بيسهل تحديد المنتجات اللي من نفس الصنف أو الكتيجوري.

## الأمان

⚠️ **النظام ده للاستخدام المحلي فقط!**  
- يوجد تسجيل دخول عند ضبط `APP_PASSWORD` في `.env`؛ لا تتركه فارغًا لو الجهاز متاح لمستخدمين آخرين.
- لا تعرضه على الإنترنت
- الـ .htaccess بيحمي الملفات الحساسة
- CSRF protection على كل الـ forms
- Prepared statements ضد SQL injection
